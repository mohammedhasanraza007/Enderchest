# CODE_MAP.md — What the code is, and how to extend it

State after Phase 6 (backend about 9,200 lines; frontend: tokens, primitives, nav capsule with Dashboard, Tasks and the bell, first run, Settings with Gemini and Notifications, the dashboard at `/` with the savings pill, Savings, the "Do I own this?" camera mode, the inventory screens, smart capture, Tasks with its 30-day road, Notifications and the item's lifecycle and maintenance). This file describes what exists; the specs say what to build. **Extend through these interfaces; never create a parallel version of a module.** Update this file in every phase that adds or changes a module. If code and this file disagree, the code wins: fix this file.

> **Read when:** before writing or changing any backend code, frontend code, scripts or tests. **Do not read when:** only reading specs.

## 2. How the backend pieces behave (the facts a new phase needs)
- **Boot:** `BootManager.run_checks()` runs in a thread at start-up and never exits the process. States: `starting`, `ok`, `recovery`, `locked`, `failed` plus a `reason`. `manager.state`, `manager.db()` (this thread's connection, for the scheduler and test routes), `manager.open_connection()` (a new one; `get_db` uses it), `manager.backups_mounted`, `manager.warnings()` (backup folder missing; stray photo files), `manager.exclusive()`, `manager.release_connections()`. Leftover `upload-tmp/*.partial` files are removed at start.
- **Routes:** use `Depends(require_ok)` or `Depends(get_db)` so a non-`ok` state answers `locked` (503). Routes are plain `def` (thread pool). Give each route a **return type or response model** (the frontend types are generated from them; draft routes use `response_model_exclude_unset` so a draft shows only the fields filled in). Add a router in `api/`, then `app.include_router(...)` in `main.py` **above** `pages.router`. Layers: route → service → repository; a route never touches SQL.
- **Transactions:** inventory services open `with write_transaction(conn):` and call several repository functions inside it (change + event commit together). Every item change writes its event (`item_created`, `item_updated` with `payload.before`, `item_deleted`, `item_restored`, `item_purged`, `label_printed`, `photo_added`, `photo_removed`, `draft_committed`). Undo (D-092) handles `item_deleted`, and from Phase 4 the lifecycle and task kinds, within 60 s; later phases add kinds to `services.undo.UNDOABLE` and its dispatch.
- **Lifecycle and reminders (Phase 4, D-104 to D-107):** the reconcile computes the desired rows (`expiry_soon`, `expired`, `inspection_due`, `task_due`, `inspection_finding`) and makes the table match inside one `write_transaction`: insert missing, reopen resolved ones that are desired again (not `dismissed`), wake snoozed ones, supersede the rest. It runs at start, when stale (date moved or 15 minutes, timing kept in memory per database), before notification reads, and after every write that changes what is due. An idle reconcile writes nothing; a timed one that changes rows on an unchanged database calls `backup.engine.note_app_write`, so the backup "changed" rule ignores it (F-022, D-108). Lifecycle actions resolve the item's rows with their own resolution; task done, skip and inspections resolve the task's rows. `shown` is an atomic claim. Undo checks `events.later_exists` (no later change to that item or task), then restores `payload.before`; the reconcile that follows reopens the reminders.
- **Items:** addressed by `public_id`; a purged id is never generated again (`items.public_id_used` checks `item_purged` events). `resolve_expiry` enforces "mode `date` ⇔ a date" for create, edit and draft commit, naming the field `expiry_date`. Lists page with an opaque offset cursor; `total` counts the same filters; `location_id` includes descendants; `q` matches the name, the public id and attribute values, never attribute keys (D-098). Category and location deletes reassign items in Trash too (D-094). Duplicate names are compared with casefold in Python (`name_taken`), because SQLite's NOCASE folds only A to Z.
- **Photos:** files are flat in `photos/` and `thumbs/` as `<uuid>.jpg` (the backup mirror reads `photos/` flat). Written to `upload-tmp/` first, then renamed; the row comes second; a failed row removes the files it just wrote. Hiding sets `deleted_at` only (the file stays). Permanent delete removes the item's files after the commit (D-096). A missing thumbnail is made again on request (thumbnails are not backed up). Files are served with `Cache-Control: private, max-age=31536000, immutable`.
- **Drafts:** one per photo, 1 to 20 per `POST /drafts`, every image checked before anything is written. Fields are merged on `PATCH`; commit validates them as `ItemCreate`, moves the photos to the item (first is primary), and is idempotent with a key; a second commit without a key is `conflict` (`reason: committed`).
- **Reading (Phase 3, D-100, D-101):** `POST /drafts` queues one local reading per new draft (`ocr_status: pending`); `POST /drafts/{id}/extract` queues `local` (Re-read) or `gemini`. Jobs open their own connection (`manager.open_connection()`), read at most 3 photos, store `ocr_result` (`engine`, `ms`, `photos`, `lines`, `proposed`, `notes`, or `error`) and never touch `fields`. The OCR job runs in `heavy.py`'s worker; Gemini jobs in their own one-worker executor (network waits). `inflight` knows what is queued: a row still `pending` that nothing holds was lost in a restart and shows as `failed` with "interrupted" until Re-read. `reading.view` builds the Draft's `proposed` (local, then Gemini where local is missing or low), `raw_text`, `ocr_error`, `gemini_error`, `read_notes`, `ocr_info`, `gemini_values`. `auto` mode asks Gemini after a local reading with neither name nor model, else `gemini_status: skipped`. Tests drain both workers before a stack closes (`tests/conftest.py::drain_readings`).
- **Gemini key:** `/data/secrets/gemini.key`, 0600, written to a `.partial` file then renamed; never returned, logged or backed up. The model name is checked (`SettingsPatch.gemini_model` pattern) because it becomes part of the URL path.
- **Database:** connections are autocommit; every write is `BEGIN IMMEDIATE`. Pragmas: WAL, `synchronous=FULL`, `foreign_keys=ON`, `busy_timeout=5000`. Never edit a released migration.
- **New migration:** add `backend/app/db/migrations/000N_name.sql` (numbers contiguous, one transaction, no seed data). Boot makes a verified `pre-migration-vA-to-vB-…` backup first. Test it like `test_boot.py::test_the_real_inventory_migration_upgrades_a_named_v1_database` (helper `v1_database` builds an older version from a temporary migrations folder).
- **Profile, settings, first run:** `first_run_step` (`name` → `categories` → `done`) is a stored settings key written by the first name save (D-093); `first_run_complete` is true only at `done`; a name with no marker (a Phase 1 database) counts as done. Settings are JSON text per `(user_id, key)`; unknown stored keys are ignored by `GET /settings`.
- **Backups:** `create_backup(settings, kind, log_conn=conn)` builds on the volume, verifies, copies to `/backups` atomically, mirrors `photos/`, writes `backup_log` with `item_count`. `has_recent_good` (verified, under 24 h, folder mounted) gates permanent delete.
- **Restore:** as before, and now reports `photos_missing` (rows whose file is in neither `/data/photos` nor the backup).
- **Security middleware:** Host must be localhost/127.0.0.1/[::1]; writes need `X-Enderchest: 1`; `Origin` must match; bodies must be JSON (at most 1 MB) except multipart on `MULTIPART_PATHS` (each image route 12 MB plus framing, `POST /drafts` 20 × 12 MB); a body must state its length (D-095). No CORS headers anywhere.
- **Errors:** raise `AppError("not_found", 404, "…")`; codes are in API.md 1. A duplicate name answers `conflict` with `details.field = "name"`; `in_use` carries `details.count` or `details.reason = "has_children"`.
- **Test stack only:** `api/test_support.py` routes exist only when `ENDERCHEST_ENV=test` and `meta.env_marker='test'`. `POST /test/fixtures/items-1000` loads 6 categories, 9 locations and 1,000 items (seeded random, 50 in Trash, 50 not active); `storyboard-1`, `-2`, `-3` load the dashboard storyboard relative to the clock's today (142, 142, 141 active items; scores 82, 86, 91; D-111) and answer the named items' public ids and the task ids.
- **Environment variables:** `ENDERCHEST_ENV`, `ENDERCHEST_PORT`, `ENDERCHEST_DATA_DIR`, `ENDERCHEST_BACKUPS_MOUNT`, `ENDERCHEST_BACKUP_DIR`, `ENDERCHEST_FRONTEND_DIR`, `ENDERCHEST_GEMINI_MODEL` (default `gemini-3.5-flash-lite`, D-102), `ENDERCHEST_BUILD_DATE`; Phase 3 adds `ENDERCHEST_GEMINI_URL` (default Google's; the test stack and tests use the closed port `http://127.0.0.1:9/v1beta`) and `ENDERCHEST_OCR_THREADS` (default 4); Phase 6 adds `ENDERCHEST_EMBEDDING_MODEL` (default `/opt/models/dinov2-small.onnx`); compose-only: `ENDERCHEST_TEST_PORT`, `ENDERCHEST_TEST_VOLUME`, `ENDERCHEST_TEST_BACKUP_DIR`, `BUILD_DATE`).

**How to extend**
- **A new screen:** `src/screens/X.tsx`, a `<Route>` in `routes.tsx` inside `AppShell`, a nav item **only when the page works** (`NavCapsule.PAGES`). Read through hooks in `api/queries.ts`; call `useRefreshInventory()` after any write that changes items, categories, locations or drafts. Every list needs loading (Skeleton), empty and error (`ErrorState`) states.
- **A new form:** keep values as text in state; validate with a pure function in `lib/`; disable the submit with `disabledReason` while invalid; on a server refusal use `splitProblems(error, SHOWN_FIELDS)` and show `general` in a `role="alert"` line (F-024); use `useUnsavedGuard` while dirty; creates send `idempotencyKey()` made once per form.
- **A new endpoint:** route with a response model, `test.bat types`, commit `openapi.json` and `schema.d.ts`, add the function to `endpoints.ts`.
- **A new primitive:** component in `primitives/`, styles with tokens only, a markup test in `primitives.test.tsx`, a gallery entry.
- **Colour, radius, duration:** only from `tokens.css`. Light theme: everything a pill, tall boxes use the soft capsule radius (`.item-tile` 40 px, text area 28 px).
- **A control that cannot act** is disabled with a visible reason; a control that cannot work is not on screen (the shutter exists only while the stream runs).
